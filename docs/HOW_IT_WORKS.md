# Как работает RocketPeak Content OS

## Текущий контур

1. Лаунчер запускает production-сборку на локальном адресе `127.0.0.1:4173`.
2. Chrome открывает приложение в отдельном окне.
3. Пользователь создаёт материал, выбирает аккаунт, каналы, дату, время и статус.
4. Изменения сохраняются в `localStorage` текущего профиля браузера.
5. Контент-план можно выгрузить в JSON как переносимую резервную копию.

Сервер Vite используется только для локальной раздачи интерфейса. Данные сейчас не отправляются во внешний сервис и не синхронизируются между устройствами.

## Разделы интерфейса

- **Очередь** — материалы, фильтры и изменение статусов.
- **Календарь** — обзор публикаций по времени.
- **Аккаунты** — карта доступных Facebook-активов и их роли.
- **Подключения** — текущий статус будущих интеграций.

## Где лежат данные

- исходный код — `src/`;
- статические файлы — `public/`;
- production-сборка — `dist/`;
- зависимости — `node_modules/`;
- Lighthouse-отчёты — `audit/`;
- диагностический лог запуска — `runtime/launch.log`;
- пользовательский контент-план — `localStorage` Chrome.

Очистка данных сайта в Chrome удалит локальный контент-план. Перед очисткой нужно сделать JSON-экспорт.

## Будущая публикация

Безопасный контур должен выглядеть так:

1. Материал подготовлен локально или на сервере.
2. Владелец проверяет текст, визуал, аккаунт и время.
3. После ручного подтверждения сервер создаёт одну задачу публикации с уникальным ключом.
4. Сервер обращается к официальному Meta Graph API.
5. Результат и идентификатор публикации записываются в журнал.
6. Повтор допускается только при безопасной ошибке и не создаёт дубль.

Личный профиль `AD Lumeo` в этот контур не входит. Через API подключаются только подтверждённые профессиональные страницы и аккаунты.

## Диагностика запуска

Если ярлык не открывает приложение:

1. открыть `runtime/launch.log`;
2. проверить, установлен ли Node.js;
3. запустить `START.cmd`;
4. открыть `http://127.0.0.1:4173/` вручную.
