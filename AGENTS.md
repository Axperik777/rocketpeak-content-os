# Правила проекта RocketPeak Content OS

## Назначение

Приложение снимает ежедневную рутину по подготовке, согласованию и планированию контента RocketPeak. Главные критерии: понятность, надёжность, скорость работы и безопасность аккаунтов.

**Рабочая папка:** `C:\Users\Mylaptop\Desktop\MARKETING\Приложение`

**GitHub:** `Axperik777/rocketpeak-content-os`

**Публичная сборка:** GitHub Pages

**Backend:** Supabase Auth, Postgres, Storage и Edge Functions.

Перед задачей прочитай родительский `C:\Users\Mylaptop\Desktop\MARKETING\AGENTS.md`, затем `README.md` и `STATUS.md` этого проекта.

## Стек

- React 19;
- TypeScript;
- Vite;
- Lucide React;
- Supabase для авторизации, базы, Storage и серверных функций;
- `localStorage` только для миграции старых данных и резервного локального состояния интерфейса.

## Правила разработки

- Интерфейс и документация — на русском языке.
- Не добавлять автоматизацию личного профиля Facebook.
- Не использовать cookies, пароли, эмуляцию действий пользователя, Selenium/Playwright для публикации и обходы антифрода.
- Интеграции Meta/Instagram строить только через официальный Graph API и системные разрешения.
- Финальная публикация должна требовать ручного подтверждения, пока владелец явно не утвердит другой режим.
- Для отправки предусмотреть идемпотентность, журнал действий, повтор с ограничением и защиту от дублей.
- Не публиковать и не разворачивать приложение во внешней среде без подтверждения владельца.
- Все файлы приложения, документация, ресурсы и runtime-логи должны находиться внутри этой папки. Допустимое исключение — ярлык на рабочем столе.
- После изменений обновлять `STATUS.md`, если фактическое состояние проекта изменилось.

## Проверка перед завершением задачи

1. `npm run build` проходит без ошибок.
2. `npm audit` не показывает известных уязвимостей.
3. Основные сценарии проверены на desktop и mobile.
4. В консоли браузера нет runtime-ошибок.
5. Лаунчер открывает приложение, HTTP-проверка возвращает 200.
